# CD-ROM Mode 1：物理映射与验收边界

2026-11-04。实现依据是 [ECMA-130 第二版（1996）](https://ecma-international.org/wp-content/uploads/ECMA-130_2nd_edition_june_1996.pdf) §14–19、附录 B/C/D/E；DiscImageStudio 仅作数值交叉核对，提交 `46fa699eb482a3915ac754d6d58a981913d9a56d`，没有移植其交织补偿代码。来源摘要及标准 PDF 的 SHA-256 见 [`sources.json`](../evidence/cd-support/sources.json)。

## 扇区与扰码

ISO 每扇区只含 2048 字节。光驱生成 2352 字节 Mode 1 扇区：同步头 `[0,12)`、地址及模式 `[12,16)`、用户数据 `[16,2064)`、EDC `[2064,2068)`、零填充 `[2068,2076)`、P `[2076,2248)`、Q `[2248,2352)`。本程序不自行向光驱发送这些原始扇区，也不实现写盘。

附录 B 明确规定每个扇区同步头之后将寄存器重置为 1；对第 12–2351 字节扰码，字节内最低位先输出。反馈为 x¹⁵+x+1，位周期 32767。前 32 字节为：

```text
01 80 00 60 00 28 00 1E 80 08 60 06 A8 02 FE 81
80 60 60 28 28 1E 9E 88 68 66 AE AA FC 7F 01 E0
```

因此用户字节 i 的主机值为 `P[i] = Q[i] XOR S[16+i]`。`S[0:12]` 在代码中补零；有效扰码在 `S[12]` 开始。2340 字节还与 [redumper 的逐字节公式](https://github.com/superg/redumper/blob/fa5d2434c755a2dc26199fee2d20fc246a9e51c9/cd/cd_scrambler.ixx) 交叉核对，不依赖其二进制程序。

## 字节顺序和 CIRC

§16 规定扰码之后，将每一对相邻字节交换：原始扇区全局字节索引 j 变为 F1 输入索引 `j XOR 1`。这和音频文件、IMAPI 的大小端传输约定是不同的步骤；输入为 2048 字节 Mode 1 ISO 时，不额外交换主机负载。

图 C.4 给出的输出关系可以直接反解。F1 中每帧 12 个双字节字（A、B）；下面列的是输出 F2 的数据槽，另有 Q 槽 12–15 和 P 槽 28–31：

| F2 槽 A/B | F1 字编号 | A/B 延迟（帧） |
|---|---|---|
| 0/1 | 0 | 3/6 |
| 2/3 | 4 | 11/14 |
| 4/5 | 8 | 19/22 |
| 6/7 | 1 | 27/30 |
| 8/9 | 5 | 35/38 |
| 10/11 | 9 | 43/46 |
| 16/17 | 2 | 65/68 |
| 18/19 | 6 | 73/76 |
| 20/21 | 10 | 81/84 |
| 22/23 | 3 | 89/92 |
| 24/25 | 7 | 97/100 |
| 26/27 | 11 | 105/108 |

实现的正向映射为 `raw_to_physical` / `user_to_physical`，逆向为 `physical_to_raw` / `physical_to_user`。后者还标记某个槽是否属于可控用户数据。图 C.4 的 24 行表达成输入字节索引后，与 DIS `DelayFor` 24 项完全相同。最短 3 帧、最长 108 帧，跨度为 106 个输出帧；不能把“一个扇区的 98 帧”理解成物理上连续的 2048 个用户字节。

每个通道帧 588 位：24 位同步、3 位合并、14 位子码、3 位合并，然后 32 个 EFM 字（各 14+3 位）。F2 槽 s 的码字起点为 `44 + 17*s`，采样中心为 `51 + 17*s`。单扇区 98×588 = **57624 位**。

## 物理域纹理与刻图

`cdimage` 按每个物理帧的两个连续 12 数据符号半帧采样设计，等价于 DVD 的 16 字节组。随后通过正向映射将目标值散填回各个用户扇区。重复字节序列取 `(physical_frame*32 + F2_slot) % len(sequence)`，计入校验槽所占的位置，不按主机字节、用户扇区或原始数据帧重新开始。`RND`、`MIX:..` 和标签数组也支持；单字节纹理天然不受排列影响。

不可控内容有 CIRC 的每帧 8 个校验、1 个子码、同步和合并位，以及原始扇区的 304 字节开销。这里的“可控字节图”不是完整坑岸图，更不是反射率预测。`efm.py` 按附录 D/E 实现参考调制，用已给出的 F3 符号做 DSV/RLL 检查；不生成 CIRC 校验和真实子码，不模拟 S0/S1 子码例外，不宣称等同于光驱的 DSV 算法。

[`efm-periods.json`](../evidence/cd-support/efm-periods.json) 使用随机校验/子码占位。在 60 个半帧内部片段中，AA 都呈 34T 周期，63 都呈 17T 周期；部分多字节候选呈 68T，但并非每次都保持。它们是参考编码器的局部数值结果，尚未验证实盘颜色，不能据此宣称整轨固定周期或覆盖率灰阶。

## 时序原点与计时模型

坐标约定：LBA 0 的第一个原始扇区从输入帧 0 开始，同步头 byte 0 交换后在 F1 槽 1。标准还允许它位于 `4n+1`，并且 §18 规定子码 Section 与 Sector 异步。刻录机内部缓冲、INDEX 01、ATIP 与此坐标的关系没有在本次测量。

采用标准正向延迟，没有套用 DIS 逆补偿流的整体 111 帧参考偏移；两者时序约定不同，不能只比较文件索引就判错。

计时模型将单扇区读完成位置设为：

```text
n_end(LBA) = ((LBA+1)*98 + 108)*588
```

原始扇区最后一对字节分别到达输出帧 202 槽 26、205 槽 27；在完整帧边界完成时就是 206 帧。此模型把尾延迟作为弧长处理，随半径转换为角度。**光驱是否确实在这一位置返回 READ(12)，以及解码是否还有随位置变化的额外延迟，都未实盘验证。**模拟器也采用这个假设，所以模拟通过只能证明软件在此假设下恢复参数。

CD 梯子以 0.5、1.5 圈起步，u/v 相对先验宽度为 8%/15%，默认 36 级、每级 32 对，固定读速 2822 kB/s（约 16x），保留 0–25 ms 随机等待、3 ms 缓存门槛、稳定转速检查及 0.2% 周期容差。没有安全候选（预测不确定度 <25°）时停止，不强行展开整圈。

## 已跑与未跑

- 所有自检通过，四组 u、v 各偏标称 ±1% 的模拟梯子在 0–85% 区间误差分别为 0.289°、0.293°、0.285°、0.289°。
- 三种 DVD 小镜像与 main 的输出逐字节一致（冻结 ISO 时间戳），原有 DVD 自检输出逐字一致。
- 新 CD 环、随机、网格、色板 ISO 全部用 Windows `Mount-DiskImage -Access ReadOnly` 挂载为 CDFS，随后卸载。
- 网格 ISO 的 **648,050,688 个可控用户字节全部**经独立输出帧枚举、CIRC 逆映射和设计比对，没有差异；只排除了 ISO 9660 的五个扇区。重建图为 [`grid-reconstructed.png`](../evidence/cd-support-20261104/grid-reconstructed.png)。重建的是 12 符号采样单元，排除了校验和光学过程。
- 未发任何实体光驱命令，未刻录。已有 ATIP 结果直接沿用目标卡与 KNOWLEDGE §4；CD 实盘 CAV/FUA、明暗顺序、颜色、网格直线度、绝对时序原点都未验证。
- 网格和色板交付镜像使用明确标为 `measured=false` 的标称几何，只供软件验收；第一次实物实验应选不需要角度标定的纹理环盘。得到随机数据盘的 CD 计时几何后，再重新生成网格与色板。
