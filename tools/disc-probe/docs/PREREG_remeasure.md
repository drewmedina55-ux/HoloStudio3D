## 要回答的问题

1. 网格扫描测到的 U 形修正，是否只是旧计时拟合里 u、v 的统计误差？
2. 计时法自己报告的 1σ 是否诚实？
3. 不用扫描仪，单靠计时能否做到约 0.1°？

## 统计量与判据

- **"真值"：**旧计时拟合（`evidence/geo/random_disc_summary.json`）加扫描修正（`evidence/angle_correction.json`）。它自身的误差取扫描噪声，约 0.04°。
- **D：**在 25.8–54.4 mm 内，新的纯计时角度映射与"真值"之差，扣除常数整体转角后的峰峰值。
- **σ_c：**√(σ_new² + 0.04²)，其中 σ_new 是新一次测量自报的 `angle_sigma_measured_span_deg`。

| 结果 | 判定 | 含义 |
|---|---|---|
| D ≤ 2σ_c | 强通过 | U 形是统计误差，误差估计诚实 |
| 2σ_c < D ≤ 3σ_c | 通过 | 同上，但证据较弱 |
| D > 3σ_c | 不通过 | 还存在一种类似 u、v 偏移的系统误差（例如固定的位置延迟）；不得写"不用扫描仪也能到约 0.1°" |
| 测量范围没有覆盖 25.8–54.4 mm | 不完整 | 只报告，不下结论 |

**写"不用扫描仪约 0.1°"的附加条件：**判定为通过或强通过，并且 D ≤ 0.15°。

## 参照：旧测量本身的位置

用同一脚本评估旧测量：D = 0.309°，σ_c = 0.130°，D/σ_c = **2.37**。按 3σ 算通过，按 2σ 算不通过，而且 D 远大于 0.15°。所以这次复测想要满足附加条件，需要明显更小的 D。

## 网格盘 3 判据修订（仍在刻录之前；上面 18:24 登记的"峰峰值 ≤ 0.15°"由本条取代）

- **为什么改：**扫描本身有精度下限。网格盘 2 的几何几乎就是真值，扫出来仍有 0.138° 峰峰值、0.040° rms。按原来的 0.15° 峰峰值判，一张好盘也很可能被扫描噪声推过线。审阅者建议改成和网格盘 2 用同一把尺子。
- **新判据（脚本 `evidence/eval_grid.py`，统计方法同网格盘 1、2）：三条都满足才算通过**
  - rms ≤ 0.06°；
  - 峰峰值 ≤ 0.20°；
  - U 形分量 ≤ 0.10°：对汇总曲线拟合 a·x² + b·x + c，其中 x = (r − 40)/14.3，取 |a|。
- **U 形阈值的标定：**审阅者原本提议 0.05°。但把脚本跑在现有两张盘上：
  - 网格盘 2：U 形 0.057°，会被判不通过，而它的几何几乎就是真值；
  - 网格盘 1：U 形 0.231°。

  所以把阈值定为 0.10°：网格盘 2 通过，网格盘 1 明确不通过。
- **对照：**
  - 网格盘 1：rms 0.093°、峰峰值 0.308°、U 形 0.231°，不通过；
  - 网格盘 2：rms 0.040°、峰峰值 0.138°、U 形 0.057°，通过。
- **通过后的写法：**#72 的标题和正文写"约 0.1°（rms ≈ 0.05°）"，并注明这是 25.8–54.4 mm 的结果，外圈 54.4–58 mm 未测。
