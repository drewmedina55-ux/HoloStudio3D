# 使用手册

各命令的原理、参数、输出和自检结果。项目介绍和快速开始见 [README](../README.md)，实验记录见 [KNOWLEDGE.md](KNOWLEDGE.md)。

## 安全

- 只发送读类命令。`discprobe/scsi.py` 里有一份白名单，白名单之外的操作码在到达设备前就被拒绝，任何写入、封盘、格式化命令都发不出去。self-test 会验证 WRITE、CLOSE TRACK、FORMAT UNIT 确实被拒。
- 唯一会改变驱动器状态的命令是 `SET CD SPEED`（调转速），而且只在你传 `--speed` 或 `--cav` 时才发送。

## 准备

1. 用**管理员**身份打开终端，否则 SPTI 可能打不开设备。也可以在命令后加 `--transport imapi`，改走 IMAPI2（`IDiscRecorder2Ex`），普通用户即可；默认的 `auto` 在 SPTI 被拒时会自动改用它。IMAPI2 还会在测量期间独占光驱、关掉换盘检测（MCN），资源管理器等程序的轮询不会插进来。
2. 电源计划切到"高性能"，减少 SATA 链路节能（ALPM）带来的延迟抖动。这一步可选，效果要实测对比。想更进一步，可以把隐藏的"AHCI 链路电源管理 - HIPM/DIPM"设置项显示出来，在电源选项的高级设置里设为 Active。显示该项的命令如下，测完可以再隐藏回去：

   ```bash
   powercfg -attributes SUB_DISK 0b2d69d7-a2a1-449c-9680-f91c70521c60 -ATTRIB_HIDE
   ```

3. 关掉其他会访问光驱的软件，比如刻录软件和自动播放。
4. 计时测试需要一张**已经刻录过、内容是普通数据**的盘，最好用 `python -m discprobe random` 生成的随机数据盘。空白区读不出东西；**刻了图案、标定图或纯纹理的盘也不行**，光驱读这种盘经常报介质错误（3/11/00），每次要重试好几秒（例外是纹理环盘里的随机数据环，以及后文 CD 路线里 DiscImageStudio 刻的音轨盘）。把整张写满：测量位置是按"已刻录容量的比例"选取的，写满才能覆盖整个半径。用 DVD-R 最好；CD-R 写成数据盘比音轨好，因为 READ CD 没有 FUA 位。

## 用法

先进入仓库目录。

列出光驱：

```bash
python -m discprobe list
```

导出驱动器和盘片信息。空白盘也能跑，可以拿到 ATIP 或 MID：

```bash
python -m discprobe info --drive E:
```

计时实验，在已刻录的盘上跑，约 1–3 分钟：

```bash
python -m discprobe timing --drive E:
```

每次读一个完整对齐的 DVD ECC 块（16 扇区），让每次读取的结束位置一致：

```bash
python -m discprobe timing --drive E: --sectors 16
```

指定读取速度（单位 kB/s；DVD 1x = 1385 kB/s，所以 8x = 11080，16x = 22160）：

```bash
python -m discprobe timing --drive E: --speed 11080
```

不接硬件，用模拟驱动器验证整套流程：

```bash
python -m discprobe selftest
```

所有结果写到 `results\` 下按时间命名的文件夹：`info.json`，或者 `summary.json` 加 `events.csv`。`events.csv` 记录每一条命令的起止时间戳，以后可以离线重新分析。

## 手动使用

下面的提示、进度和动画只在标准输出是终端时出现。管道、重定向和脚本调用得到的输出和以前一样，结果文件的格式也没变。在终端里想关掉它们，设 `DISCPROBE_PLAIN=1`。

**新手教程。**第一次在终端运行 `guide` 时会问要不要看一遍，回车或 `y` 看，`n` 跳过，只问一次；已经有真实测量结果的不会问。之后想看就运行：

```bash
python -m discprobe tutorial
```

**下一步跑什么。**`guide` 读 `results` 文件夹，列出做过的步骤，打印下一条命令，不碰光驱。不带参数运行 `python -m discprobe` 也是它。`guide --media cd` 看 CD 的步骤；不写时跟随最近一次测量的盘型。

```bash
python -m discprobe guide
```

在终端里，步骤会一直列到图片镜像和刻盘，并标出现在到哪一步。程序不负责刻录，看不到你刻没刻，所以最后一步不会打勾。`iso` 文件夹里有了图片镜像后，`guide` 还会讲怎么看盘（不要正对着）和看到不同结果该怎么办。这一段是按现有文档和命令整理的，实际走一遍后可能还要调整。

`info`、`timing`、`geo`、`random`、`image`、`disexport` 跑完也会打印下一步，`timing`、`geo`、`random`、`image` 还会在前面列出进度（模拟驱动器的结果不算进度）。`timing` 还会给判定：不是 CAV 就换速度，抖动大于约 2° 建议降速，大于约 5° 说明这台光驱很可能不适合（这两个门槛来自实践报告表，不是严格界限）。`geo` 中途停下时，会按停下的原因给建议。`geo` 跑完也会给一句结论，并把角度不确定度（测量范围内的 1σ）换算成 50 mm 半径处的距离。χ²/dof 不超过 2 且不确定度不超过 0.25° 才算好；0.25° 以上是能用但噪声大，0.6° 以上是噪声太大，都会建议换个速度或换光驱。只看 χ²/dof 不够，因为噪声大的光驱误差棒也大，拟合照样好看。这两个门槛来自本仓库的完整测量（干净的运行是 0.10–0.15°，不能用的 3226 rpm CD 是 0.77°）和 `timing` 的抖动门槛的换算，不是严格界限，外部报告大多没有这个数，所以没有用它们验证过。χ²/dof 超过 2 说明偏差比噪声大，它会自动比较恒定轨距和二次轨距：二次模型把 χ²/dof 至少降一半，就让你先写修正文件，后面的命令也带上它；否则说明多半是读取噪声，可以继续。这个比较在关闭光驱之后做，不影响测量。和本节其他提示一样，判定和下一步只在终端里显示，管道和脚本里只有数字。

**盘符。**`list` 列出光驱。在终端里可以不写 `--drive`：只有一台就直接用，有多台就问你。盘符写错时，报错里会列出现有的光驱。

**结果路径。**`image`、`tiles`、`beacons`、`disexport` 的 `--geo` 除了 `summary.json`，还接受结果文件夹和 `latest`。`latest` 选最近一次完整的真实测量，会跳过模拟驱动器的结果和中途停下的结果，并打印选中的是哪一次。提前停止的结果会在 `summary.json` 里写 `stopped`；之前版本留下的结果没有这一项，只能按少于 8 级或 χ²/dof 超过 25 判断，8 级以上中途停下的分辨不出来。明确写结果文件夹时仍然可以用提前停止的结果，打印的说明里会标出来。`results` 列出做过的测量，最新的在前：

```bash
python -m discprobe results geo
```

脚本里要路径的话，用 `results geo --latest`，它只打印一行文件夹路径。

**选一次历史结果。**`latest` 取最新一次可靠的结果，判定噪声太大的会被跳过。想自己选的话，运行 `python -m discprobe results --pick`，或者在命令里写 `--geo pick`。第一级按盘和光驱分组，进入后按精度或日期排序：`s` 换排序，`r` 反过来，回车选择，左键返回，`q` 退出。不在终端时它只打印列表。2026-11 之前的结果没有记录盘型，会按时间相近、容量相同的 `info` 记录匹配，并标上 `~`。

**`--sectors` 有三个意思。**`timing`、`geo` 里是每次读几个扇区，`16` 读一个完整的 DVD ECC 块（`geo` 只接受 1 或 16，CD 上只能是 1）。`random` 里是刻多少，要放得下。`disexport` 里是盘的容量，必须填，DiscImageStudio 里也要填同一个数，否则外半径会变，填多了还可能封盘失败。以前 DVD 不填时默认 2298496，比一些盘的实际容量大（[#107](https://github.com/JiaFeiMiao-K-Cat/DiscImageStudio/discussions/107#discussioncomment-19440415) 里的盘是 2295104），所以改成了不填就报错并给建议值。`info` 会在终端打印建议值，并说明来源：空白盘优先用剩余空间，CD 用 ATIP 的导出区起点，已刻录的盘用最后一个 LBA 加一（只有整张刻满时才等于空白盘的容量）。以空白盘上 `info` 的数为准。DiscImageStudio 的"从光盘读取"读到的数不同时，也以 `info` 为准：domerawind [报告](https://github.com/JiaFeiMiao-K-Cat/DiscImageStudio/discussions/107#discussioncomment-19442161)它比实际能写的多（RITEKF1 2298496 对 2297888，mini DVD-R 714546 对 713936），照它填就封盘失败。原因已经查明：DVD-R 上多出的 608 扇区是收尾要用的边界开销（TBO 592 加 BSGA 16），见 DIS 作者在 [#183](https://github.com/JiaFeiMiao-K-Cat/DiscImageStudio/issues/183#issuecomment-6691519009) 的说明，这个数不能推广到所有 DVD。按 2297888 重新拟合的预设[封盘正常](https://github.com/JiaFeiMiao-K-Cat/DiscImageStudio/issues/183#issuecomment-6690200194)（一张盘）。

**`--speed` 怎么选。**可以写 kB/s，也可以写倍速，如 `4x`（`--media cd` 时按 CD 的 1x 换算）。低速通常噪声更小，但不是每台光驱都会换档，要看 `timing` 打印的转速。

| | 常用值 |
|---|---|
| DVD（1x = 1385 kB/s） | `2.4x` = 3324，`4x` = 5540（`geo` 默认），`8x` = 11080 |
| CD（1x = 176.4 kB/s） | `8x` = 1411（`--media cd` 默认），`16x` = 2822，`24x` = 4234 |
| 蓝光（1x = 4495 kB/s） | `8x` = 35960，`12x` = 53940。倍速按盘的实际类型换算；目前报告过的蓝光光驱都是恒定线速度，换速度不一定成 CAV，`geo` 也不支持蓝光 |

**`--ranges` 怎么选。**默认的已刻录区 3%–85% 适合大多数盘，一般不用改。它接受 LBA 范围 `a-b,c-d`。`geo` 总在同一个 LBA 附近停下，或者外圈有换速跳变时，把那段排除；想覆盖更大的半径，可以加宽，前提是光驱读得干净。测到外圈不等于外圈就会准：GP65NB60 加宽后测到 58.09 mm，二次修正后只剩 0.092°，用户仍反馈最外圈的径向线略翘。最后一个 LBA 看 `info`。

**CD 和 DVD。**步骤相同，每条命令加 `--media cd`，它同时把默认值换成 CD 的。终端里如果盘是 CD、命令却是 DVD 设置，会先问要不要加。托盘开着、光驱里没有盘或认不出盘时，`timing`、`geo`、`info` 都会直接说，管道里也一样。`disexport` 按 `--geo` 的结果决定预设类型，它的 `--media` 只用来核对。

**中途出事。**测量时开仓或盘被取出，读取会返回 `2/3A`（GH70N 上实测是 `2/3A/02`，开仓后第一次读要等约 4 到 5 秒，之后每次约 5 ms 就失败）；换过盘按标准会返回 `6/28`，这个还没有实测过。读到这些，`timing` 和 `geo` 会立刻停下并说明原因，退出码 1，不再把剩下的读取空跑完。“正在加载”（`2/04`）可能只是短暂状态，连续 100 次才停。只有读取失败才走这些判断，正常读取的时序不变。Ctrl+C、光驱消失这类情况也算提前停止。已测的部分会保留并标明提前停止，`guide` 不打勾，`--geo latest` 不用它。

写镜像被中断（出错、Ctrl+C、磁盘满）时，没写完的文件会被删除。参数检查没通过、文件还没动过时，旧镜像不受影响。写的时候旁边有一个 `.writing` 标记文件：进程被杀或窗口被关时来不及清理，它会留下，`guide` 就不会把那个文件当成写好了，下次写同一个文件时会先清掉。不过直接拿那个残缺文件去刻，程序拦不住。

**Tab 补全。**运行一次下面这条命令，之后 `--sp` 按 Tab 就补成 `--speed`，`--media` 后按 Tab 列出 `dvd`、`cd`，`--geo` 后可以选 `latest`。

```bash
python -m discprobe completion install
```

它会在主目录写一个脚本，并在 shell 的启动文件（PowerShell 的 `$PROFILE`、`~/.bashrc` 或 `~/.zshrc`）里加一行。**当前窗口还不能用**：新开一个窗口，或者运行它打印的那一行。`completion uninstall` 会把这两处都删掉，其他内容不动。说明文字跟随当前语言，也可以加 `--lang zh` 或 `--lang en`。不想让它改启动文件的话，`completion` 不带参数会打印手动步骤。

在 PowerShell 上，`discprobe` 这一行按 Tab 会弹出列表，列出选项、参数类型和说明，其他命令的 Tab 不变（已经自定义过 Tab 的不会被改动，可以按 Ctrl+Space 看列表）。`python <Tab>` 在仓库目录里会先给 `-m discprobe`。命令和选项的位置不会补文件名。bash 和 zsh 只补全文字，不显示说明。如果 PowerShell 的执行策略（ExecutionPolicy）不允许运行脚本，它不会改启动文件，也不会改策略，只告诉你怎么办，要不要放开由你决定。

按 Tab 时不会启动 Python：所有命令和选项都已写进脚本，shell 只在当前命令的选项里比对前缀。所以 disc-probe 更新后要重新生成一次。它按 `python -m discprobe` 这几个词识别，其他 `python` 命令照常补全文件路径；不过 bash 和 zsh 原本针对 `python` 的专用补全会被替换。

**语言。**在终端里默认跟随系统语言：系统是中文就显示中文，帮助、提示、测量输出都一样。繁体系统目前也显示简体。想手动指定，用 `--lang zh` 或 `--lang en`，放在命令任何位置都行；也可以设环境变量 `DISCPROBE_LANG=zh`。管道、重定向和 `DISCPROBE_PLAIN=1` 始终是英文，脚本不受影响，`DISCPROBE_LANG` 对它们也不起作用；只有在命令里明确写 `--lang zh` 才会变成中文（输出为 UTF-8）。`summary.json` 等结果文件和 `selftest` 的输出不翻译。

```bash
python -m discprobe --lang zh guide
```

**进度。**`timing` 和 `geo` 显示进度条、当前阶段、已用时间和预计剩余时间；写 ISO 和检查写入内容时用同样的状态行，进度来自文件的实际大小。窗口窄时依次省掉按键提示、已用时间、进度条，不会折行。百分比向下取整，只有做完才显示 100%；刚变化的那一位数字会闪一下，100% 时变绿。终端通过 `COLORFGBG` 说明背景是深色时用亮绿，其他情况用终端主题自己的绿色。按 Ctrl+C 会保留已测的部分并说明位置，退出码 130。

在 Windows Terminal、ConEmu、Ghostty、kitty、WezTerm 等支持 OSC 9;4 的终端里，标签页和任务栏按钮也会显示进度，结束时清除。宽窗口里 `timing`、`geo` 的进度行还有最近 12 次定时读取耗时的小图，方块越高读得越慢，每次都按这 12 次的范围缩放，只用来看抖动的样子，不是测量结果。这些读数只在读取之后的等待里记录。窗口变窄时，已知会重新折行的终端会清掉折出去的部分；其他终端可能留下一截残影，不影响数据。

**数据行。**在终端里，`timing` 的 Zone 和 Target 行按列对齐，只补空格和四舍五入去掉的末尾 0，数值不变。管道和脚本拿到的还是原来的字节。

**镜像生成后。**`random`、`image`、`tiles`、`beacons`、`rings`、`calib` 生成完镜像，会在一行里单独打印完整路径，并闪烁红字警告：DVD+R、DVD-R、CD-R 刻录后不可撤销，只有 RW 盘能擦除。程序不读光驱，所以不知道你手上是哪种盘，也拦不住刻录。用模拟几何生成的图片镜像不闪，因为它本来就会提示不要刻。Ctrl+C 只跳过闪烁，红字还在；`--no-animation` 时直接显示红字。在 Windows 上还会用低可视度提示确认刻录机选对了盘符，因为刻录窗口可能默认指向别的盘。

**在终端里摆放图片。**`python -m discprobe edit my_picture.png` 会在终端里显示一个小盘面，灰色部分不能绘制。方向键移动，`+` `-` 改大小，`[` `]` 旋转，`,` `.` 调整亮度多低时变暗，`a` 自动找一条合适的明暗界线（Otsu 算法），`i` 反转明暗，`c` 切换到裁切（再按依次换左、右、上、下边，第五次回到移动），`Tab` 切换粗细步长，`u` 撤销，`0` 重新开始，回车保存，`q` 退出。裁切按图片自身的上下左右算，图片转过角度时，方向键和屏幕方向可能不一致；剪掉后其余部分留在原位。它保存一个小小的设计文件（默认是图片名加 `.design.json`），里面只记录图片路径和这些参数，不碰光驱。然后用 `python -m discprobe image --geo latest --design my_picture.design.json --output iso/picture.iso` 生成镜像。不做任何调整时，结果和 `image --picture` 完全相同。手机竖拍的照片会按拍摄方向摆正，`image --picture` 也一样。再次打开时，写图片名或设计文件都可以。图片要留在原处，或者和设计文件一起移动。

`image` 用图片或默认网格时，结束前会画一张约 40 × 40 像素的盘面缩略图，方向和预览图相同（数据面视角），灰色部分刻不了。用 `--picture` 时还会提醒这些情况，每次最多三条：几乎全黑或全白、深色内容落在可绘制区域之外或盘中间、图案只占很小一块、图不是正方形、分辨率过低或过高、灰度过多。这些只是提醒，不会阻止生成，门槛是先定的保守值，还没用真盘校准。

**小游戏。**测量时按 `g`，进度行下方会打开一款游戏，`n` 换下一款，`q` 关闭。测量输出照常打印在它上方，不会被盖住。不按 `g` 就没有这些。它们需要动画和键盘，所以管道、`DISCPROBE_PLAIN=1`、`--no-animation` 下都不会出现；`NO_COLOR` 时用字符画。窗口放不下某一款时会跳过它。

| 游戏 | 玩法 |
|---|---|
| 贪吃蛇 | 方向键或 WASD 转向，`r` 再来一局 |
| 刻满 | 方块从右边飞进来往左堆，上下移动，右键旋转，左键快落，排满一列就消掉并得分，堆到右边就结束，`r` 再来一局 |
| 合并扇区 | 方向键滑动，相同的块合并翻倍，从 `2K` 开始（`32K` 正好是一个 DVD ECC 块），放不下时 `r` 再来一局。棋盘留到下次等待接着玩 |
| 数独 | 方向键移动，数字键填，`0` 或空格清除，冲突的数字变红，解开后 `r` 再来一盘。每盘只有一个解 |

数独的大小在第一次轮到它时决定，这次运行不再改：估计还剩 30 秒到 2 分钟是 4×4（2×2 宫），2 分钟以上是 6×6（2×3 宫），不足 30 秒不提供。还没有估计时，`timing` 按 90 秒算，`geo` 按 300 秒算。

它们和进度行一样没有后台线程：读按键、移动、绘制都在计时读之前的随机等待里完成，而且只画变化的格子，用的是各自的随机数。合并扇区的存档只在进度行关闭时写，绝不在两次读取之间写。在模拟驱动器上，相同种子下边玩四款游戏边测，`summary` 和事件与不玩时逐条相同。真实光驱上没有对比过；要测重要的盘，就别按 `g`。

**本地文件。**除了 `results` 和生成的镜像，程序只在 `%LOCALAPPDATA%\disc-probe\`（其他系统是 `~/.local/state/disc-probe/`）写两个小文件：`games.json` 存合并扇区的棋盘和最高分，`tutorial_offered` 记录问过教程。存档读不出来时就开新局，写不进去也不影响测量。Tab 补全写的文件见上面。这些都可以直接删除。

动画仍是每秒最多 8 帧，和之前的进度行一样，但带颜色的单帧写的字节比之前多。`timing` 比较过旧进度行：有无它的差别（0.01–0.20°）和重复测量的差别（0.02–0.23°）相同。新动画和 `geo` 都还没在真实光驱上比较过，介意的话加 `--no-animation`，或者用管道、`DISCPROBE_PLAIN=1` 跑。

`timing` 和 `geo` 测量时会把进程调到高优先级。2026-11-06 之前的版本在 64 位 Python 上这一步一直失败，所以之前用 64 位 Python 跑的真实测量都是普通优先级，上面的比较也是；实践报告表里用这个工具在 Windows 上测的数据多半也是，用移植版或别的探针测的不一定。高优先级对抖动的影响还没有比较过。

为了不干扰测量，进度行没有用后台线程。ctypes 在 ioctl 期间释放 GIL，读取返回时如果别的线程正占着 GIL，完成时间戳最多会晚一个 5 ms 的切换间隔，而被测的抖动只有几十微秒。所以进度行在主线程里，趁每次计时读之前的随机等待来画，花掉的时间从等待里扣。这段等待本来就是随机的。在模拟驱动器上，相同种子下加不加这层包装，`summary` 和事件逐条相同；真实光驱上还没有对比过，介意的话用管道或 `DISCPROBE_PLAIN=1` 跑。

**外观。**`guide` 开屏下方有一句问候，一周里同一时段总是同一句，只是闲聊，不代表测量结果。`guide` 开头有一张光盘，彩虹光带转半圈后停下。动画按时钟走，终端慢时会跳帧，不会拖长。按终端能力逐级退回：

- Windows Terminal、Ghostty、WezTerm、kitty 和 Claude 桌面应用的终端会自己绘制方块字符，所以在这些终端里（需要 UTF-8 和真彩色）盘面是半块像素，只发送变化的格子。光带从白色过渡到紫、红，接近真盘的衍射。做过的步骤越多，轨道从内向外染得越深。
- 其他真彩色终端：盘面是彩色空格，中间用 `/`、`\` 标出光带，经过的地方闪几个 `*`、`+`、`.`。
- 再往下是 16 色和纯文本。窗口窄或矮时只显示标题或一行文字。

进度行上有一个转动的小光盘，当前阶段的文字上每隔一两秒扫过一道彩虹光，文字本身保持终端的默认颜色，深色和浅色主题都看得清。转动只是装饰，不代表实际转速。上面这些终端里，进度条是线条样式，按半格移动，已完成的部分偶尔掠过一道高光。其他终端默认全用 7 位 ASCII，不受代码页和字体影响，比如 Windows 自带的旧控制台窗口；终端字体够用的话，`DISCPROBE_UNICODE=1` 可以手动换成更细的图形。

| 环境变量 | 作用 |
|---|---|
| `DISCPROBE_PLAIN=1` | 关掉所有提示、进度、动画和中文，和管道相同 |
| `DISCPROBE_LANG=zh` 或 `en` | 在终端里指定语言 |
| `DISCPROBE_NO_ANIMATION=1` | 和 `--no-animation` 相同：保留颜色和数字，不要动画，也没有小游戏 |
| `DISCPROBE_UNICODE=1` | 在 UTF-8 终端上手动换成更细的图形；上面列出的终端不用设 |
| `DISCPROBE_NO_TUTORIAL=1` | 不询问新手教程，`selftest` 也用它 |
| `NO_COLOR=1` | 只关颜色，动画保留 |
| `CI=1` | 不要动画 |

标准输出不是终端或 `TERM=dumb` 时什么都不画。

**常见报错。**缺 numpy、scipy、Pillow 时会打印安装命令。`--geo` 的文件不存在，或者不是 `geo` 的结果，`--ranges` 格式不对，`--drive` 打不开，都改成了一行说明，退出码仍是 1；参数错误的退出码仍是 2。

## `info` 读了什么

INQUIRY、GET CONFIGURATION（当前 profile 和功能列表）、READ DISC INFORMATION、READ TRACK INFORMATION、READ CAPACITY、TOC、ATIP（CD-R 的导入起始时间可以识别染料厂商，最大导出时间就是容量）、DVD 物理格式信息（标称位长和轨距档位、PSN 范围）、DVD-R 预刻信息（0Eh，含 MID）、DVD+R ADIP（11h，含 MID）、GET PERFORMANCE（读写速度随 LBA 的曲线；纯 CAV 下首尾速度比就是外/内半径比）、MODE SENSE 2A（缓存大小、转速控制方式、写速列表）。

每条命令都保存原始十六进制。解析失败或驱动器不支持的项会单独列出，不会中断其余命令。

## `timing` 做三个实验

1. **cache**：对同一个扇区连续读 40 次，分三种方式：普通读、带 FUA 读、先发一条零长度带 FUA 的 READ(12) 再普通读（redumper 用这个办法清缓存）。中位耗时低于 3 ms 说明数据来自缓存（慢速连接上的缓存可能更慢，所以还会和 FUA 的耗时比较）。由此按以下优先级选定后续读取策略，并记录每种方式耗时的 P50/P95/P99：
   - `plain`：驱动器本来就不缓存重复读；
   - `fua`：FUA 有效；
   - `flush`：FUA 被忽略，但零长度 FUA 读能清掉缓存；
   - `evict`：以上都不行，每次测量前先在别处读一段数据把缓存挤掉，并丢弃疑似缓存命中的样本。
2. **period**：在内、中、外三个区重复读同一扇区，用周期图（Rayleigh periodogram）从完成时刻估计转一圈的周期 T，给出 rpm、抖动（µs 和度）。三个区的 T 相同说明是 CAV；T 随半径增大说明是 CLV，这时相位法不成立，会打印警告。
3. **phase**：交替读参考扇区 R 和目标扇区 X，计算 X 的完成时刻相对 R 的主轴相位。在 CAV 下，这就是两个读块末端在盘面上的夹角，再加一个固定的解码延迟项，对 360° 取模。随机的寻道时间不影响结果。主轴的慢漂移用 R 的残差插值扣除。输出每个目标的相位均值、单次标准差、均值标准误（sem）和样本数。

## 结果怎么看

- `cache.strategy`：`fua` 或 `plain` 最好；`evict` 也能用，但更慢、噪声更大。
- `period.rotation.mode`：必须是 `CAV`，相位法才有意义。如果是 CLV，先用 `--speed` 换一个速度档再测。`--cav` 设置的是 SET CD SPEED 的 Rotational Control 位，但 MMC 把这一位定义为写入时的转速控制，所以它对读取有没有作用，只能看周期测试的结果。
- 每区的 `jitter_deg`：单次测量的角度噪声，直接决定精度。估算方法：平均 n 次后误差约为 `jitter_deg / sqrt(n)`。
- `phase.targets[].phase.sem_deg`：每个目标相位的不确定度。模拟中真实误差的离散比它大约多 10–20%，可以当作略偏乐观的估计。这些相位是对 360° 取模的，要拿去解缠和拟合 r0/b、p/b，还需要下一步的分析（另写）。
- `timing` 遇到连续读取错误会提前停止并说明原因；周期测试判定不是 CAV 时跳过相位测试（`--force` 可强制继续）；总时长默认不超过 15 分钟（`--max-minutes`）。
- `info` 里 Page 2A 的 "rotation CLV" 说的是**写入**时的转速控制，不代表读取方式，要看 `timing` 的周期测试。
- 每次计时读之前的随机等待（`--host-delay-ms`，默认 25 ms）应当**长于一圈**。转速低于 2400 rpm 时一圈就超过 25 ms，要调大，比如 30–40 ms。

## 背景资料与首轮实验建议

以下来自研究报告，其中引用源码的部分我已核实过。

- **先例。** Philips 专利 US7538787B2（盘面写标签）描述的方法和本探针相同：用读完成时刻定位扇区；重复读同一个 ECC 块测转速周期；拟合时把跳读距离逐级翻倍。所以方法本身有先例，但它在现代 SATA 光驱上能达到多少精度，仍要实测。
- **候选型号的原厂读取规格。**
  - HLDS GH24NSD5 读 DVD±R 单层时为 6.6–16x CAV、9360 rpm，一圈约 6.41 ms；
  - Lite-On iHAS124 F 读 DVD±R 的各速度档全部是 CAV。

  这台贴牌机的 OEM 还没有确认，不能直接套用这些规格。
- **读取结束到底对应盘面上哪个位置，是最大的未知数。** 主机看到的完成时刻 = 物理读到的位置 + 固件和传输延迟。如果这段延迟随地址变化，那么即使所有闭环检查都通过，它也会被误拟合成"轨距变化"。所以必须用辐条盘扫描做一次独立对照。
- **建议的首轮对比实验**，都在已刻录的单层 DVD±R 上做：
  - 默认参数跑一遍，再加 `--sectors 16` 跑一遍，比较两次的相位曲线是否一致（差一个常数是允许的）；
  - 分别用 `--speed 11080` 和 `--speed 22160` 跑；
  - 把盘取出、重新放入后再跑一遍，看结果能否重复。

## 模拟驱动器

`discprobe/sim.py` 模拟了这些行为：CAV 主轴（带约 2 ppm/s 漂移）或 CLV（每次寻道后重新锁速）、随机寻道时间、带预读的缓存（FUA 可以被设置成无效）、解码延迟、60 µs 主机抖动和 1% 的大离群值。盘片几何故意偏离标称值。self-test 在五种配置下跑完整流程，再与模拟器的真实几何比较：

- CAV 下，FUA 有效时分别用 1 扇区和 16 扇区读取；
- CAV 下，FUA 无效但零长度 FUA 读能清缓存；
- CAV 下，以上两种办法都无效，只能挤掉缓存；
- CLV。

每个目标读 40 对，相位误差在 0.8°–2.2° 之间。在 8 个随机种子上统计，误差没有偏差，离散约为报告标准误的 1.1–1.2 倍。

模拟只证明分析数学和流程是对的，不代表真实驱动器的表现。真实的抖动、缓存行为和转速策略，要等实测。

## 真值测量：辐条盘 + 平板扫描

这部分用来给光驱计时法提供一个独立的对照：烧一张辐条图案盘，平放在扫描仪上扫描，测出图案在每个半径上实际转了多少度。

### 原理

图案在模型坐标下是三组正弦辐条（k = 3、21、63，即每圈 3、21、63 个周期）。DiscImageStudio 按自己的几何模型给每个字节取亮度，所以如果模型和实际盘面有偏差，烧出来的辐条在半径 r 处会整体转过一个角度 δ(r) = 实际角度 − 模型角度。也就是说，δ(r) 正是我们想要的"弯曲曲线"。

分析程序先在扫描图里定位盘心，再把图像按 0.05 mm 一圈切成同心环，对每个环做傅里叶分析，提取三组辐条的相位：

- k = 3 用来沿半径方向解缠；
- k = 21、k = 63 依次对齐到 k = 3 上，最终精度由 k = 63 决定；
- 半径 26、32、38、44、50、56 mm 处各有一圈 0.5 mm 宽的均匀灰环作为标记。它们在扫描里表现为辐条信号消失的地方，从而给出"模型半径 → 实际半径"的对应。

这个方法有几个不容易出错的性质：

- **盘心定位误差和扫描仪 x/y 缩放差，影响很小。** 这两种误差造成的角度偏移在一圈内一正一负，整圈平均后一阶抵消。
- **不受光照和衍射彩虹干扰。** 光照不均和扫描仪的衍射彩虹主要在 k = 1、2 两个频率上，而辐条在 k = 3、21、63。判断"有没有辐条"用的是该频率相对邻近频率的信噪比，而不是相对整圈亮度的方差。
- **镜像和反色都能处理。** 扫描图是否镜像，会自动识别并校正；明暗是否反了，对结果没有影响。

### 步骤

1. 生成图案。DVD 用 `--radius-mm` 等于工程的生成外半径（默认 58）；CD 用 57.5（DiscImageStudio 的 CD 画布半径固定是 57.5 mm）：

   ```bash
   python -m discprobe spokes --output spokes.png --radius-mm 58
   ```

   同时会生成 `spokes.spokes.json`，分析时要用到。

2. 在 DiscImageStudio 里把 `spokes.png` 作为图层导入，居中，并让图片正好铺满画布。缩放稍有偏差不影响角度测量，只会让标记环的"模型半径"不准。抖动保持默认开启即可。然后用你要标定的那套参数（比如某个预设）生成或刻录。

3. 扫描：数据面朝下放在扫描仪玻璃上，用 600 dpi、灰度或彩色，存成 PNG 或 TIFF（不要用 JPEG）。盘放在哪个位置、转成什么角度都可以。不要盖着标定板一起扫，否则会干扰找盘边。

4. 分析：

   ```bash
   python -m discprobe scan scan.png --spec spokes.spokes.json
   ```

### 输出

- `phase.csv`：每个半径一行。`delta_rel_deg` 是相对最内圈有效环的弯曲角度；`snr_k*` 是三组辐条的信噪比；`good` 标记该环是否参与了结果。
- `summary.json`：盘心位置、扫描仪 y/x 缩放比、是否镜像、每环噪声、各标记环的实际半径等。
- `detect.png`：缩小后的扫描图，叠加了识别出的外缘圆和中心孔。先看这张，确认盘找对了。
- `unrolled.png`：把盘面按 (半径, 角度) 展开成矩形，最内圈在上。如果参数不准，辐条会显示成弯的。
- `unrolled_corrected.png`：每一行按测出的 δ(r) 反向平移后的结果。辐条变成笔直的竖线，说明测量正确。

### 自检结果

合成测试模拟了一次扫描：弯曲曲线 −3°～220°、半径缩放 0.2%、扫描仪 y/x 缩放差 0.3%、盘心偏离扫描图中心、任意转角、二值抖动纹理、比辐条还强的 k = 2 彩虹、光照梯度、噪声，并分别测试正常和"镜像加反色"两种情况。结果：

- 弯曲曲线恢复误差最大 0.23°，rms 约 0.04°；
- 镜像识别正确；
- y/x 缩放比恢复到 1.003；
- 6 个标记环的半径误差都在 0.016 mm 以内。

### 还没验证的

真实扫描里图案到底看不看得见、对比度有多少，只能实测。可以先用一张已经刻过的盘扫一下，看刻录区的纹理是否明显。

如果盘的参数偏差很大，图案在相邻两个环之间（0.05 mm）就会转过 60° 以上，k = 3 的解缠会失败。这时 `good` 的环会变少，`unrolled.png` 会显示成密集的螺旋。应该先用一套大致准确的预设，而不是完全按标称值去烧。

## 纹理环测试盘：找出能用的灰阶

目的：在普通 DVD±R 上，找出 A5（暗）、92（亮）之外还有哪些"纹理"能稳定地显出中间亮度。这张盘**不需要任何几何标定**。

### 原理

DVD 刻录时，光驱会先把每个扇区的 2048 字节用户数据和一个扰码序列做异或（ECMA-267 第 16 节），再做 EFMPlus 调制。要让盘上实际刻下的字节等于 Q，写进 ISO 的字节就得是 P = Q XOR 扰码。扰码序列只有 16 种，由物理扇区号的第 7～4 位选择，所以同一个 ECC 块（16 扇区）内用同一种序列。`discprobe/dvd.py` 的实现与 DiscImageStudio 的 `DvdDataFrameBuilder` 一致。

测试盘由一圈圈同心环组成，每个环只刻一种 Q（或随机数据）。环只跟半径有关，几何参数差 1% 也只是让环的边缘挪动约 0.25 mm，而扫描分析会实测边缘位置。

默认布局是 7 种纹理（A5、B9、66、64、E4、92、随机），每环宽 1.4 mm，从 25 mm 排到 54.4 mm，内、中、外共 3 组，ISO 约 4.0 GB。每组的排列顺序都错开，避免某种纹理总在同一个相对半径上。25 mm 以内用 92 填充。

### 步骤

1. 生成 ISO。只看布局、不写文件，加 `--describe`：

   ```bash
   python -m discprobe rings --output rings.iso
   ```

   写完会自动抽查每个环的扇区，确认解扰后确实是目标字节。同时生成 `rings.rings.json`，分析时要用。

2. 刻录：用刻录软件的"写入映像"功能把 `rings.iso` 刻到 DVD±R 上。Windows 自带的"光盘映像刻录机"就可以。镜像在 LBA 16–20 带有一个空的 ISO 9660 文件系统（只占 25 mm 以内的填充区，不影响图案），这是为了让刻录软件接受它；刻好后在资源管理器里看到的是一张空盘。记下盘的品牌、MID（`info` 能读到）和写入速度，这几项都可能影响结果。

3. 先用眼睛看：在台灯下和漫射光下，各个环能不能分出深浅。

4. 扫描：数据面朝下，600 dpi，**彩色**，存成 PNG 或 TIFF。关掉扫描软件里所有自动调整：自动曝光、色阶、锐化、去网纹、色彩恢复。建议同一张盘扫 3 次，每次把盘转 90°，用来估计重复性和光照方向的影响。

5. 分析（可以一次传入多张扫描图）：

   ```bash
   python -m discprobe ringscan scan1.png scan2.png scan3.png --layout rings.rings.json
   ```

### 分析做了什么

- **测环边缘。** 按半径取亮度中位数，在每个环的预测边缘附近找亮度变化最陡的位置，再拟合 r² = a + c·LBA。这样得到每个环的实际半径，顺便测出 r0 和"轨距×扇区长度"相对标称值的比例。这只是径向几何，不涉及角度。
- **消除光照影响。** 扫描仪的灯光和盘面的衍射彩虹会让亮度和对比度随角度、半径变化。所以每 5° 一个角度区间，把 3 组的 A5 环、92 环分别对半径做线性拟合，再把每个环换算成"等级"：0 = 同一位置的 A5，1 = 同一位置的 92。
- **挑调色板。** 每种纹理的等级在各组、各张扫描图之间汇总，算出重复误差 σ。按从暗到亮排序，相邻两档至少差 3σ 才算一档，以此给出建议调色板。

### 输出

- `textures.csv`：每种纹理在 L（亮度）和 R、G、B 各通道上的平均等级和标准差。
- `rings.csv`：每张扫描、每个环的明细，包括实际半径、等级、原始亮度，以及亮度随角度的变化幅度。
- `summary.json`：径向拟合结果、各纹理等级、两两之间相差几个 σ、建议调色板和警告。
- `unrolled_*.png`：盘面按（半径，角度）展开，内圈在上，左侧标出纹理名，红色短线是拟合出的环边缘。先看这张，确认环的位置对得上。

### 注意

- **等级的含义。** 等级只在扫描仪输出与反射率成线性关系时才是线性的。普通 8 位 PNG 一般带 gamma，所以等级的先后顺序可信，间距会有失真。
- **扫描仪能分开，不等于肉眼能分开。** 只有肉眼也能分出来的档位，才放进最终调色板。
- **R、G、B 通道的差异。** 如果某种纹理在三个通道上的等级明显不同，说明它带来了颜色变化，这条线索和衍射彩色有关。

### 自检结果

- 扰码寄存器的周期为 32767（x¹⁵+x⁴+1 是最长序列），16 种预设各不相同。
- 小规模 ISO 写入后能逐一校验；故意翻转一个字节，校验能发现。
- 合成扫描的条件：实际 r0 为 23.96 mm，"轨距×扇区长度"比标称大 0.8%；光照随角度和半径变化；每个环随机偏差 0.01 级；66 和 A5 完全一样暗。结果：
  - 22 条环边缘全部找到，r0 恢复到 23.9597 mm，比例恢复到 1.00795，边缘 rms 0.003 mm；
  - 各纹理等级误差不超过 0.010；
  - 建议调色板为 66 64 E4 B9 RND 92，正确地把 A5 和 66 合并成一档。

## 多假设标定盘：两张盘、两次扫描，测出整张盘的几何

用户提出的思路：先假设一个几何参数，画出图案，扫描后看扭曲了多少，反推出真实参数；再在一张盘上并行试多个假设。这一节就是它的实现。

### 为什么要分两张盘

几何参数差 1%，在 1 mm 宽的半径范围内，图案就会多转约 5 圈，扫出来只是一片灰。所以第一张盘的任务只是"找到大致范围"，第二张盘再把精度做上去。

### 第一张：括号盘（bracketing）

- 盘面分成 39 条细环带（每条约 0.62 mm），之间隔着 0.2 mm 的纯 92 保护环。
- 每条环带画三重辐条，但用的"假设"不同：把标称几何的局部转速乘以 1+s，s 从 −1.2% 到 +1.2%，每档 0.2%，共 13 档。
- 这 13 档在内、中、外各排一遍（3 组），所以每个半径附近都有一组完整的假设。
- 刻上真实盘以后，只有 s 和真实转速误差相差不到约 0.15% 的环带能看清辐条，其余环带都糊成灰色。

分析程序 `calscan` 的做法：

1. **定位环带。** 用保护环的边缘拟合 r² = a + c·LBA，确定每个扫描环对应的扇区号。
2. **测每条看得清的环带。** 辐条随半径转动的速率，直接给出该处的真实局部转速。
3. **粗拟合。** 两条以上、位于不同半径的环带，就能线性解出 u = r0/b 和 v = p/b，这是决定所有角度的两个比值。
4. **细拟合。** 所有环带共享同一个未知的整体转角，所以把相位也联合起来拟合。每条环带的"半径误差"作为一个带先验（10 µm）的未知量一起拟合，免得扫描仪的微小半径误差把结果带偏。
5. **镜像和反色。** 辐条里有一个与三重分量锁相的九重分量，图案因此有手性，扫描图是否镜像会自动识别；明暗颠倒不影响结果。

### 第二张：精修盘（refinement）

用第一张的拟合结果，把所有 20 条环带都按同一个（已经很准的）几何来画。这时每条环带都"对上了"，相位不再受半径误差影响，精度由相位噪声决定。这相当于牛顿法的第二步，只需要这一步。

### 步骤

1. 生成第一张盘：

   ```bash
   python -m discprobe calib --output iso/cal1.iso
   ```

   如果你已有更接近的参数（比如 DiscImageStudio 某个品牌的预设，或纹理环盘测出的 r0），可以用 `--r0-mm/--pitch-um/--bit-nm` 让扫描范围以它为中心。

2. 刻录、扫描（与纹理环盘相同：600 dpi，无自动调整，存 PNG/TIFF），然后分析：

   ```bash
   python -m discprobe calscan scan1.png --layout iso/cal1.cal.json
   ```

3. 用第一张的结果生成第二张盘，刻录、扫描、分析：

   ```bash
   python -m discprobe calib --refine-from results\calscan-...\summary.json --output iso/cal2.iso
   ```

   ```bash
   python -m discprobe calscan scan2.png --layout iso/cal2.cal.json
   ```

4. 第二张的 `summary.json` 里，`fit.dis_equivalent` 给出可以直接填进 DiscImageStudio 的参数：位长 133.3 nm 时的内半径，以及按你的盘总扇区数算出的外半径。

### 输出

- `bands.csv`：每条环带一行，包括是否看得清、看不清的原因（糊了／转太快／不直）、测出的局部转速误差 `s_local_needed`、细拟合是否接纳、拟合残差，以及拟合出的半径偏移。
- `phase.csv`：每个扫描环的信噪比和相位。
- `summary.json`：u、v、按 133.3 nm 换算的 r0 和轨距、24–58 mm 范围内角度的不确定度、标称几何原本偏了多少度，以及 `dis_equivalent`。
- `unrolled.png`：展开图，左侧标出每条环带的 s。绿色表示看得清，灰色表示看不清。

### 自检结果

合成盘的真实几何：r0 23.95 mm，轨距 0.7365 µm，位长 133.6 nm。在 24–58 mm 范围内，它比标称几何多转约 64000°。

| | 看得清的环带 | 24–58 mm 角度误差 | 报告的 1σ |
|---|---|---|---|
| 括号盘，正常扫描 | 9 / 39 | 1.3°（粗拟合 13°） | 2.3° |
| 括号盘，镜像加反色 | 9 / 39 | 4.7°（粗拟合 12°） | 2.3° |
| 精修盘 | 20 / 20 | **0.08°** | 0.023° |

- 括号盘的误差主要来自"半径误差先验"：没有完全对上的环带，半径每差 1 µm，相位就差几度，所以这里只能做到几度。这已经足够让精修盘的每条环带都对上。
- 精修盘报告的不确定度偏乐观（实际误差约是它的 3.5 倍），判断时留些余量。

### 还没验证的

- **可见性。** 环带中每个字节按概率取 A5 或 92，扫描仪看到的是两者的平均亮度。实盘上这种混合纹理的对比度够不够，要看第一张盘。纹理环盘也能先回答这个问题。
- **扫描仪本身的几何误差。** 局部拉伸、周期性误差都还没测；棋盘格标定板可以用来查。精修盘结果的可信度取决于这一点。
- **假设范围。** 默认只覆盖 ±1.2%。如果第一张一条看得清的环带都没有，可以加宽到 ±2.5%：`--s-range 0.025 --s-step 0.0025 --groups 2`（每档仍有重叠）；或者把中心参数移到别的位置再试。

## 计时测几何："梯子"测量（`geo`）

不用扫描，直接让光驱测出一张已刻录盘的螺旋几何。

### 原理

光驱匀速旋转时，读完参考扇区 R 和目标扇区 X 的时间差换算成转角，就是两个 ECC 块末端在盘面上相隔的角度（再加一个常数 c，即两次解码延迟之差，理想情况下约为 0）：

φ(X) = Θ(n_X) − Θ(n_R) + c（对 360° 取模）

其中 Θ(n) 与标定盘用的是同一个模型，只由 u = r0/b、v = p/b 两个比值决定。

难点在于只能测出"对 360° 取余"的角度，而标称几何在远距离上会差几千圈。所以测量像爬梯子一样逐级展开：

1. **稳住转速。** 反复读参考扇区，直到测出的周期不再变化。
2. **第一级。** 先测离参考 1.5 圈和 4 圈的位置。标称模型在这么近的距离只差几度，因此能定出 c。
3. **逐级外推。** 每测一级就拟合一次 u、v、c（对 u、v 加宽松先验），然后挑"预测误差小于 25°"的候选里离参考最远的一个作为下一级。整圈数由预测值决定，测完再拟合。每一级都让模型的预测更准，可达距离成倍增加，DVD 默认测 22 级、CD 默认测 36 级，就能覆盖整个可读半径。
4. **检查转速。** 每一级都会重新测参考扇区的周期。如果转速在测量中途变了，就先等转速稳定再重测。

### 用法

```bash
python -m discprobe geo --drive H:
```

- 开始测量前先比较内外圈的转速。如果光驱是 CLV，几秒内就停下并说明原因，不会花很长时间只得到几个没用的点。设置速度可能让一些光驱离开恒定转速，而且要重新放盘才恢复。这时重新放盘，确认 `timing` 显示 CAV，再用 `--speed keep`，它不发设速命令，光驱保持现状。
- 默认测已刻录区域的 3%–85%，读速固定在 4x（`--speed 5540`）。外圈约 53 mm 以外这台 GH70N 会换转速，所以默认避开。
- 只想用纹理环盘上的随机数据环：

  ```bash
  python -m discprobe geo --drive H: --rings-layout iso/rings.rings.json --texture RND
  ```

  纯单字节纹理（尤其 `64`、`92`、`66`）在这台光驱上会读得很吃力，触发重试，转速也会跟着变。
- 输出：
  - `targets.csv`：每一级的测量相位、预测值、整圈数、拟合残差；
  - `summary.json`：u、v、按 133.3 nm 换算的 r0 和轨距、测量范围内及 24–58 mm 范围内的角度不确定度、`dis_equivalent`。

### 在这台光驱上的实测要点（GH70N，Ritek F1 DVD-R）

- **缓存与 FUA。** 不加 FUA 重复读同一扇区约 1.1 ms，是从缓存返回的；加 FUA 后约 42–47 ms，才是真正读盘。缓存判断门槛已从 1 ms 改为 3 ms。
- **整圈问题。** 加 FUA 时，每次重读都固定耗费整数圈，所以必须在每次读取前随机等待 0–25 ms（`--host-delay-ms`），否则只能测出"几圈"的总时长。模拟器已加入这种行为（`reread_delay_ms`）。
- **转速。** 读速固定 4x、稳定约 30 s 后，转速为 2831 rpm（一圈 21.195 ms），26–47 mm 范围内不变。
- **精度。** 随机数据区单次相位标准差 0.43–0.55°，40 次平均后 ±0.07–0.09°。
- **自检。** 模拟器上，14 级梯子在盘面 0–85% 范围内的角度误差约 1°，与报告的 1σ 一致。
- **实盘。** 在纹理环盘的 3 个随机数据环（33.6–45.8 mm）上跑了 21 级：残差 rms 0.096°，常数 c = −0.009°，测量范围内 1σ 为 0.13°。详见 [KNOWLEDGE.md](KNOWLEDGE.md)。

## 刻图、纹理与颜色

计时测得几何以后，可以直接按这套几何生成可刻录的 ISO（Windows 光盘映像刻录机就能刻），不需要拍照描点。作品照片见 [`showcase/`](showcase/README.md)。

**刻图（`image`）：**
- 默认生成网格测试图；`--picture` 用一张灰度图（阈值化），长边对应 `--diameter-mm`（默认 116 mm）并保持比例，不足的地方留白；大图也能用，但比这个尺寸多出的细节会被缩掉；`--design-npy` 用 6000 × 6000、每格 0.02 mm 的设计数组（数据面视角，y 朝上）。
- 布尔设计用 `--dark`、`--light` 两种纹理（建议 `A5` 和 `92`）。uint8 标签设计配合 `--textures`，按标签顺序给出每种纹理：单字节（`A5`）、按数据帧列定相位的重复序列（`8B00`）、随机数据（`RND`）或随机混合（`MIX:92,4F`）。
- 例：
  ```bash
  python -m discprobe image --geo <summary.json> --design-npy design.npy --textures RND A5 92 8B --output pic.iso
  ```
- 每次生成后都会抽查扇区，与设计逐字节核对。

**纹理与颜色：**
- `discprobe/efmplus.py`：带 DSV 选择的 EFMPlus 编码器（移植自 DiscImageStudio）。用来预测刻录机实际写出的坑岸图案，搜索周期纹理（`evidence/coverage/`）。它也证明了：大面积的坑/岸覆盖率被刻录机的 DSV 控制钉在 50%，可见对比只能来自游程类和沿轨衍射。
- `tiles`：自定位色板靶盘。每块带差分编码的编号（明暗翻转也能读）和一组纹理色块；`--ring-edges`、`--tile-mm`、`--cols`、`--scale` 可以调整布局。
- `tilescan`：读取平板扫描，先除去扫描仪的逐列条纹，再自动找旋转和镜像，读编号、量色块。
- `discprobe/tilephoto.py`：读取手机照片。用盘缘椭圆和盘心的像求消失线，拟合单应矩阵，再用编号校验。`tools/flash_lut_tiles.py` 用闪光灯照片算出相机位置，建立"纹理 × 观察几何 → 颜色"的对照表。

**观看建议：**彩虹"披萨片"是出厂导槽的衍射。在一块小而亮的光源的镜面方向附近看（光源紧挨着眼睛或相机），图像整盘可见。详见 [`KNOWLEDGE.md`](KNOWLEDGE.md) §10–§10f。

## CD-R：纹理、计时与刻图

`rings`、`random`、`timing`、`geo`、`image`、`tiles` 和 `gridscan` 支持 `--media cd`，默认仍为 DVD。CD 单扇区为 57624 通道位；实现和时序假设见 [CD 物理模型](CD_PHYSICAL_MODEL.md)。测量和网格盘这部分在 HL-DT-ST GH70N 和 CMC CD-R 上实测过，换光驱或换盘要重新验证。

第一次做 CD，先照 [README 的 CD 路线](../README.md#cd-路线)走，至少要 3 张同批的空盘（测量、标定、刻图）。这一节是各步骤的细节和其他做法。

想先看不同数据刻出来的明暗，可以刻一张无需角度标定的纹理环盘：

```powershell
python -m discprobe rings --media cd --output iso/cd-rings.iso
python -m discprobe ringscan scan1.png scan2.png --layout iso/cd-rings.rings.json --refs 0D,AA
```

默认 15 环，26–56 mm，纹理 `0D,AA,10,63,RND`；CD 布局会自动选择 `0D,AA` 作为扫描参考，也可用 `--refs` 改成实测最暗和最亮的两种。ISO LBA 16–20 留在内侧背景。CD 镜像超过 **359,849 扇区**会报错，不自动裁短，也不覆盖同名 CD 镜像或侧车文件。

**刻录。**Windows 的 IMAPI2 把 CD 数据写成 Mode 2 Form 1，用户数据从扇区第 24 字节开始，所以 `--cd-sector` 默认是 `mode2form1`；按 Mode 1 的偏移预扰码，纹理会变成噪声。IMAPI 收尾需要留一点空间：359,847 扇区的盘上 359,800 扇区的镜像被拒绝，359,600 可以。GH70N 上用 8x 刻录，40x 时出现过 SATA 复位。

```powershell
python -m discprobe random --media cd --output iso/cd-random.iso
powershell -ExecutionPolicy Bypass -File tools/burn_imapi.ps1 -Drive H: -Iso iso/cd-random.iso -Speed 8 -Burn -Reload
```

刻录时光驱不报进度，脚本每 30 秒打印一行已用时间和按写入速度估的剩余时间。刻完托盘会弹出，`-Reload` 只是再把它收回来，不会提前打开托盘；超薄光驱要自己推回去。托盘开着时跑 `timing` 只会报托盘开着。

**测量。**先刻随机数据盘，再计时。要用低转速：GH70N 在 `--speed 2822`（3226 rpm）下，49.8 mm 以外的完成时刻会晚约 0.2 ms，`--speed 1411`（约 2080 rpm）下没有这个现象。

```powershell
python -m discprobe timing --media cd --drive H: --speed 1411
python -m discprobe geo --media cd --drive H: --speed 1411 --host-delay-ms 35 --ranges 2000-356000
python tools/geo_polyfit.py results/geo-H-... --write-correction correction.json --phi-degree 7
```

`geo_polyfit.py` 会打印各阶多项式的留一法误差，用它选阶数。这批 CMC 盘的轨距有波浪，恒定轨距 rms 0.233°，二次 0.163°，七次 0.080°。

**沿轨道常数。**计时测不出"数据沿轨道的绝对位置"，所以 CD 测完几何还差这一个常数。它会让径向线按 `c + a/r` 的形状扭转。这个值在不同路径上差别很大：GH70N 加 IMAPI（Mode 2 Form 1）约 206 帧；TSSTcorp SN-208FB 加 cdrdao（Mode 1，[DiscImageStudio #130](https://github.com/JiaFeiMiao-K-Cat/DiscImageStudio/issues/130)）约 7 帧，这个值来自一张照片的拟合，还没用第二张网格盘验证。所以不要直接套用别人的数。定这个常数有下面两条路。

**推荐：交给 DiscImageStudio 的精细标定。**用 `geo` 代替它的粗标定和边界标定，少刻盘，也少描点。沿轨道常数的效果只相当于内半径变化约 0.3 µm（206 帧），精细标定本来就在拟合半径，按推算能把它一起吸收，不需要刻网格盘。这条路来自 kasumikira（[#107](https://github.com/JiaFeiMiao-K-Cat/DiscImageStudio/discussions/107#discussioncomment-19415813)）和 pugod124（[disc-probe #2](https://github.com/Ashley-QwQ/disc-probe/issues/2#issuecomment-6650565706)）的 CD-R 实测，我们自己还没有走过。

1. 导出预设。`--sectors` 用空白盘上 `info` 给的数，DiscImageStudio 里也填这个数；扇区数不同，外半径也会不同。它的**从光盘读取**读到的数不同时，以 `info` 为准（见上面“`--sectors` 有三个意思”）。

   ```powershell
   python -m discprobe disexport --geo <summary.json> --correction correction.json --sectors <扇区数> --output dis_preset_cd.json --install
   ```

   `disexport` 看 `summary.json` 里的 `media`，CD 的结果导出 CD 预设（`sectors`、内外半径、三个轨距系数，速度固定 1200 mm/s）。`--sectors` 必填，拟合范围默认用 `geo` 测到的范围。预设和测量结果相差超过 5° 时不写文件。加 `--install` 会顺便把预设写进 DiscImageStudio 的用户预设文件（`%LOCALAPPDATA%\DiscImageStudio\disc-presets.json`）；文件在别处或不在 Windows 上时用 `--dis-presets 路径` 指定。写之前先备份成 `disc-presets.json.<日期>-<时间>.bak`，每次用新名字，不会把上一份覆盖掉。文件里的注释和尾逗号能读，但写回时会去掉（这个会提示）。模拟盘的结果、中途停下的结果和 `results` 判为噪声太大的结果会被拒绝；CD 音轨的结果照常安装，它本来就是给 DiscImageStudio 的音轨路径用的。`--output` 和 `--dis-presets` 指向同一个文件时会直接报错，什么也不写。这个程序不写的字段会原样保留，但它的值要是已经不适用了（比如 `usableSectors` 大于这次的扇区数），就会把它删掉并在输出里说明——DiscImageStudio 会因为这一个字段拒绝整个文件。`summary.json` 里没有噪声、chi2 这类质量数字时仍会写入，但会先提示那项检查没能做。不加 `--install` 则只生成 JSON。

2. 用了 `--install` 就重启 DiscImageStudio，在预设列表里选新预设；只有写了 `--output` 才会另外生成文件。如果第 1 步没加 `--install`，二选一：在标定页手动填内外半径、扇区数和三个系数；或者把输出里 `preset` 这个对象加进 `%LOCALAPPDATA%\DiscImageStudio\disc-presets.json` 的 `cdPresets` 数组，再重启程序（格式见它的[预设文档](https://github.com/JiaFeiMiao-K-Cat/DiscImageStudio/blob/main/docs/DISC_PRESETS.md)。moodyos 用这个办法导入成功了，我们自己没有试过）。
3. 在辅助标定页直接选**精细标定**，新建标靶，刻盘，拍照矫正，沿一条十字线细臂描点，再反推并应用。拟合三次轨距至少要 12 个不同半径的点，覆盖环带宽度的 60%。步骤见它的[辅助标定说明](https://github.com/JiaFeiMiao-K-Cat/DiscImageStudio/blob/main/docs/CALIBRATION.md)。
4. 应用后保存为预设，用这组参数刻图。

它的 CD 标定盘输出是 `.wav` 或 `.raw`，成品图可能走 Mode 1 数据盘。两条刻录路径的沿轨道位置是否相同，我们没有验证过；如果成品的线又扭了，先查这一点。

**不想手动描点：刻网格盘。**用自己估的常数生成网格盘，没有估值就填 0，刻好后看径向线的扭转，再修正常数。网格的方格线间距 5 mm，会造成每 5 mm 一个假峰，所以只能用径向线判断（`evidence/cd-geo-20261104/grid2-scan/grid_spokes.py`）。常数可以从扭转量反推：拟合 `c + a/r`，一帧的轨道长度约 0.163 mm，`|a|`（弧度·mm）除以 0.163 就是当前用的常数和真实值之差（帧）。#130 就是按 206 帧刻了一张，从扭转量得出差 199 帧。平板扫描不一定看得清（#130 的扫描仪只有约 3/255 的差别），可以改用灯光下拍照。

```powershell
python -m discprobe image --media cd --geo <summary.json> --correction correction.json --along-track-frames <帧数> --output iso/cd-grid.iso
```

定好常数后，这个数也可以传给 `disexport --along-track-frames`，直接导出预设。不传时输出会提醒径向线可能是扭的。CD 预设已经有人实刻过：moodyos 不做精细标定，轮廓和原图一致；FanJZSS 用 `--along-track-frames -100` 导出，和 DIS 精细标定只差约 2 帧。两者都是用户反馈，详情见 [README 的表](../README.md#有实践报告的光驱)。

**另一条路：直接测 DiscImageStudio 刻的音轨盘。**DiscImageStudio 可以把图刻成一条音轨（CD-DA）。`geo --media cd` 在这种盘上改用 READ CD，每次计时读之前先读远处的一个扇区挤掉缓存（不够时自动加到 2、4 个，再不行才退回数据盘用的 1024 扇区挤缓存）。原点用 DiscImageStudio 自己的：第 k 扇区在刻进去的音轨字节流里结束于第 2352(k+1) 字节。所以测出来的就是这种盘该填的内外半径，`summary.json` 里的 `dis_equivalent` 按盘上的扇区数直接给出，数据盘路径上的 108 帧读尾和 206 帧沿轨道常数都用不到。

剩下的只有一个常数：这台光驱的 READ CD 在扇区末尾之前多少字节完成，用 `--read-offset-bytes` 给出，记进 `summary.json`。HP BU20N 是 0（用实刻的直线核对过）；PLDS DU-8A5LH 约 −603 字节（由同一张盘和 BU20N 的结果对出来）。换一台光驱读，先用一张实刻的直线核对一次。

```powershell
python -m discprobe geo --drive E: --media cd
python -m discprobe geo --drive E: --media cd --read-offset-bytes -603
```

这种结果用 `disexport` 导出预设，不需要也不接受 `--along-track-frames`。`image` 和 `tiles` 写的是数据轨，起算点不同，所以会拒绝这种结果，它们仍然要用数据盘测出的结果。

测的是盘本身的几何，和刻它时填的参数无关，所以用名义参数刻一张探测盘就够了。在 BU20N 上测一张 banana CD-R，结果和另一套独立的程序（[dis-cd-timing](https://github.com/WindowsNoEditor/disc-probe/tree/dis-cd-timing/contrib/dis-cd-timing)）只差 +5 nm / −4 nm，按那套程序的结果刻的直线是直的。

`image --media cd` 同样接受布尔/标签 `--design-npy`、`--textures`、`--picture`。用 `--picture` 时，半径 26 mm 以内自动留空，那里放着文件系统。绘图单元改为物理帧中连续的 12 数据符号；重复纹理按"物理帧号 ×32 + F2 槽"定相位，再通过 CIRC 映射回填用户数据。暗/亮默认 `0D`/`AA`，设计应在内侧留出背景，文件系统扇区与图案相交时会拒绝生成。CD 计时结果带 `media=cd`，禁止把 DVD 的拟合直接用于 CD 刻图。

CD `tiles` 的编号参考改用 `0D`/`AA`，`tilescan` 和 `tilephoto` 复用原来的编号和几何处理；分析输出中的历史字段名 `levels_a5_0_92_1` 对 CD 表示编号的 `0D=0 / AA=1`。重复序列如 `0DAA`、`00FF` 是待测候选，不保证光驱产生整轨固定周期。CD 导槽衍射更靠近镜面方向，拍摄宜使用视角小于 10° 的小光源，先锁定观察几何。

运行 `python -m discprobe selftest` 可验证扰码、CIRC 正逆映射、独立反向重建、破坏检出、模拟梯子、合成扫描及参考 EFM 的 3T–11T / DSV 一致性。软件验收数据在 [`evidence/cd-support/`](../evidence/cd-support/selftest-final.txt) 和 [`evidence/cd-support-20261104/`](../evidence/cd-support-20261104/validation.json)。实测结果见 [`KNOWLEDGE.md`](KNOWLEDGE.md) §12。
