# 彩色靶盘 v3 拍摄方案（`iso/colour3.iso`）

## 这张盘是什么

- **两圈共 27 块瓦片**，每块约 18 mm 宽。每块左侧 4 列是编号区（`A5`/`92`），右侧 3 列共 9 个色块，每个约 4.5 mm（径向）× 2.5 mm（切向），面积约是 LUT 靶盘 v2 色块（3.2 mm × 0.95 mm）的 3.7 倍。
- **9 种纹理**：

  | 纹理 | 用途 |
  |---|---|
  | `B9` | 待查的异常纹理 |
  | `F9` | 与 B9 理想一维谱完全相同（只差平移），是同谱对照 |
  | `92` | 8T，16T 周期，已知能显色 |
  | `66` | 4T，8T 周期 |
  | `B797439866` | 纯 5T，周期 1.33 µm |
  | `4AD4B2` | 纯 6T，周期 1.60 µm |
  | `C0CDE6B2D1CB3E` | 纯 7T，周期 1.87 µm |
  | `B7B2` | 5/6T 比例与 B9 相同，但排列不同（5-5-5-5-6-6） |
  | `F9FD457C989AD4828671B2` | 平衡的 5-5-6-6 |

  5T/6T/7T 序列来自 6pro 的研究，已经用我们自己的编码器复核：各自约 100% 是目标游程。
- **位置随机化**：每 9 块瓦片构成一个拉丁方，每种纹理在 9 个格位里各出现一次。全盘共 3 组，每种纹理在每个格位都恰好出现 3 次，邻居也会变。这样"纹理"和"在瓦片里的位置"不再绑定。
- 瓦片之间留 1 mm 随机数据间隙；外圈有角度刻度。

## 方案 A（主实验，不需要新工具）：手机和闪光灯固定，转盘

目的：让**同一个物理色块**依次经过正、负 δ。这是现有数据最缺的一块。

1. 盘放在深色绒布上，数据面朝上。房间关灯，只留一点暗的均匀环境光，保证编号读得出来。
2. 手机固定在支架上：
   - 高度约 15 cm；
   - 镜头离盘心水平约 8 cm；
   - 镜头对准盘心，整张盘在画面里，尽量占满。
   拍摄期间手机**完全不动**。
3. 闪光灯常开。长按对焦并锁定 AE/AF。关闭夜间模式和实况照片，选主摄 1x。
4. 按外圈刻度，每次把盘转 30°，每个角度拍 1 张，转满一圈共 12 张。
5. 把离轴距离改成约 5 cm，再转一圈，拍 12 张。
6. **量一下闪光灯相对镜头的位置**：在拍摄时的握持方向下，闪光灯中心在镜头中心的哪个方向、多少毫米（iPhone 17 Pro 可查 Apple 尺寸图：相对主摄横向 43.66、纵向 19.79 mm，相对超广角横向 43.66、纵向 0.55 mm；其他手机自己量，可能比想象的远）。分析时用它修正 δ（`flash_lut_tiles.py --flash DX DY`）。

## 方案 B（角度扫描）：相机和盘都固定，移动屏幕上的小光点

目的：把"颜色"拆成"在哪个角度最亮"。用单一基色，看 B9 的亮度峰出现在 92 峰的约 1.5 倍 δ 处，还是根本没有。

1. 盘平放，显示器竖直放在盘的一侧，相机固定，**不开闪光**。房间全黑。
2. 用浏览器打开 `tools/primary_spot.html`，按 F11 全屏。默认是 9 × 5 个位置、4 mm 的光点；按 H 隐藏文字后拍摄。
   - 空格：下一个位置
   - 1 / 2 / 3：红 / 绿 / 蓝
   - 先只用**绿色**扫一遍，45 张。
3. 量三个数，用于计算光源方向：
   - 屏幕平面到盘心的水平距离；
   - 屏幕可视区下沿离桌面的高度；
   - 屏幕可视区左沿相对盘心的左右偏移。
4. 开拍前，先开灯（或开闪光）拍一张**定位照片**。相机和盘都不动，45 张光点照片共用这张照片的单应矩阵，不用逐张读编号。
5. 曝光固定。光点很暗，可能需要较长曝光，可以用三脚架加定时。

## 格式

- 先照常用 JPEG（"兼容性最佳"）拍，现有流程直接能用。
- 6pro 建议用线性 RAW。但我们的环境里没有 DNG 解码库，装 `rawpy` 需要你同意。ProRAW 也不是传感器原始读数（它已经去马赛克，还可能是多帧合成）。所以第一轮用 JPEG 加锁定曝光，只在线性度确实成为问题时才考虑 RAW。

## 刻录

这张盘需要一张新的 Ritek F1 DVD-R。镜像为 `iso/colour3.iso`（4.68 GB）。

刻录命令（需要你同意，并确认放入的是空盘）：

```
isoburn.exe /Q H: "D:\disc-probe\iso\colour3.iso"
```
